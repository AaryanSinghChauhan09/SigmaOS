# AI Agent Guidelines: Canary Value Management in SigmaOS

## Overview
This document defines operational guidelines and architectural directives for AI agents working on **Canary Value Management** in SigmaOS. It specifies the stack canary generation protocols, thread-local Stack Smashing Protection (SSP), LSB null-byte formatting rules, OpenBSD-style context switch canary verification, and kernel fault recovery routines across `#![no_std]` security modules in SigmaOS.

## 2. Architectural Rules & Canary Formatting Invariants

AI agents must enforce the following 4 core invariants when implementing or auditing canary value mechanisms:

```
+-------------------------------------------------------------------------+
|                  SIGMAOS CANARY VALUE GENERATION                        |
+-------------------------------------------------------------------------+
                                     |
              +----------------------+----------------------+
              |                                             |
              v                                             v
  [Thread-Local SSP Canary]                   [Kernel Global Canary]
  • LSB Forced Null Byte: 0x00                • Seeded with 0xDE0D_CAFE_BAAD_F00D
  • Terminates C-string Overflows             • Checked at Function Return
  • Indexed by Thread ID                      • Verified During Context Switch
```

### 1. LSB Null-Byte Formatting (Linux SSP Parity)
- **Invariant:** Thread-local guard canaries generated by `BinaryProtectionManager::generate_canary(thread_id)` MUST set the Least Significant Byte (LSB) to `0x00`:
  ```rust
  let canary = (raw_entropy & !0xFF) | 0x00;
  ```
- **Rationale:** Since string copy functions (`strcpy`, `sprintf`) terminate on NUL bytes, forcing `0x00` in the LSB prevents attackers from leaking or overwriting the canary via string-based buffer overflow vulnerabilities.

### 2. Dynamic Entropy Base
- **Invariant:** Stack canaries must never use hardcoded static constants in production.
- **Rule:** `StackCanary::new()` in `src/security/hardening.rs` initializes the canary base dynamically via `canary_base()` mixed with a generation multiplier (`0x9E3779B97F4A7C15`).

### 3. OpenBSD-Style Context Switch Validation
- **Invariant:** In `src/kernel/roundrobin.rs`, context switching routines MUST validate the CPU context `stack_canary` before restoring registers or PCID mappings.
- **Fault Handling:** Mismatched canary values during context switches MUST trigger a kernel security fault (`__stack_chk_fail`), halting the corrupted thread before privilege escalation can occur.

### 4. Zero Ring 0 Panic Rule
- Canary verification routines (`verify_canary`, `verify_stack_canary`) must return an explicit `Result<(), &'static str>` or `bool` status instead of triggering unhandled kernel panics.
