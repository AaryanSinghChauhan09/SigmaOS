# AI Agent Pull Request Management Protocol for SigmaOS

This document specifies mandatory protocols, procedures, and governance standards for AI agents (Jules, Sentinel, Bolt, Palette, and subagents) managing Git branches, commits, pull requests, and code submission workflows in the **SigmaOS** repository.

---

## 1. Branch Naming Conventions

All AI agent feature implementations, bug fixes, and documentation updates MUST be executed on dedicated topic branches following these naming patterns:

- **AI Agent Working Branches**: `jules-<task_id>` or `agent-<persona>-<feature>` (e.g., `jules-18088526978288456857-83ee2796`, `agent-sentinel-pqc-enclave`).
- **Feature Branches**: `feature/<component>-<description>` (e.g., `feature/kernel-eevdf-scheduler`).
- **Fix Branches**: `fix/<component>-<bug_description>` (e.g., `fix/sigpkg-universal-adapter-match`).
- **Docs Branches**: `docs/<topic>-update` (e.g., `docs/agents-pr-management`).

---

## 2. Commit Message Standards

Commits generated by AI agents MUST strictly follow **Conventional Commits** formatting rules:

```
<type>(<scope>): <short summary (50 characters max)>

[optional body explaining 'why' and key changes]

[optional footer]
```

### Allowed Commit Types:
- `feat`: New feature or capability addition.
- `fix`: Bugfix or CI repair.
- `docs`: Documentation updates.
- `refactor`: Code cleanup or deduplication without functional change.
- `test`: Addition or modification of unit/integration tests.
- `ci`: Changes to GitHub Actions workflows or scripts.

### Rules:
1. **Subject Line**: Maximum 50 characters, imperative mood ("Add feature" not "Added feature").
2. **Body**: Blank line between subject and body. Detail the root cause, fix, and verification steps.
3. **No Secrets**: Subject and body MUST NEVER contain credentials, API tokens, or hardcoded passwords.

---

## 3. Pull Request Size & Granularity Guidelines

To ensure rapid code review, maintainability, and green CI builds:
- **Small PRs (`size/XS` to `size/M`)**: Target under 500 lines changed per PR wherever possible.
- **Atomic Scope**: Each PR MUST address a single logical feature, bugfix, or documentation unit.
- **De-duplication Audit**: Before opening a PR, run code deduplication checks to ensure no duplicate type namespaces (`E0428`) or impl blocks (`E0592`).

---

## 4. Pull Request Description Template

AI agents MUST format PR descriptions with high clarity and actionable context:

```markdown
## Summary of Changes
- Concise list of code, config, or documentation changes introduced.

## Issue / Task Context
- Explains the problem solved, root cause, or feature requirement.

## Verification & Test Results
- [x] Executed `./run_sigma_tests.sh` with 100% pass rate.
- [x] Verified `cargo check --lib` produces 0 compilation errors.
- [x] Confirmed `AGENTS.md` and security checklists are satisfied.

## Pre-Commit Verification Gate Completed
- Called `pre_commit_instructions` and implemented reviewer feedback.
```

---

## 5. Automated CI Checks & Review Gates

Every Pull Request submitted by an AI agent MUST pass all automated CI check suites:
1. **Rust Toolchain Gate**: `.github/workflows/*.yml` step using `dtolnay/rust-toolchain` MUST specify `with: toolchain: stable`.
2. **Unit & System Test Gate**: All 224 Rust unit tests, 11 security input validation tests, and 14 Python integration tests MUST pass via `./run_sigma_tests.sh`.
3. **Code Review Tool Gate**: Call `request_code_review` and address any identified blocking feedback prior to merging or submitting.
4. **Memory Recording**: Call `initiate_memory_recording` to persist architectural patterns and task solutions for future AI agent runs.
