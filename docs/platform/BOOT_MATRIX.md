# SigmaOS Platform Boot & Validation Matrix

This document tracks verified boot evidence across supported target architectures, execution environments (QEMU vs. Bare-Metal Hardware), and kernel release milestones.

## Evidence & Verification Principle

> **Code in repository does not imply bootability.**
> Every claim in this matrix must link to a CI run log, artifact digest, or diagnostic report generated by `scripts/ci/qemu_boot_smoke.sh` or `tests/boot/boot_to_shell_test.py`.

## Boot Lifecycle State Machine Requirements

Every validated boot sequence must pass through the following 5 state markers:

1. **`SIGMAOS_BOOT_INIT`**: Multiboot2 / UEFI handoff header validated.
2. **`SIGMAOS_MMU_INIT`**: 4-Level page tables established with W^X executable space protection.
3. **`SIGMAOS_KERNEL_MAIN`**: Ring 0 kernel main execution, syscall dispatcher (`Posix450SyscallDispatcher`), and interrupt vector table initialized.
4. **`SIGMAOS_DRIVERS_INIT`**: Core boot drivers (VirtIO-GPU, 16550 UART, NVMe/VirtIO-Block) attached.
5. **`SIGMAOS_SHELL_INIT`**: Userland init process spawned (`/sbin/init` or `ZenithShell`) with interactive TTY prompt listening.
