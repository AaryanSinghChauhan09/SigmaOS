🧩 Microkernel Variants

<512 KB kernel, <8 MB RAM footprint. All non-essential services run as isolated user-space shards communicating via sigma-bus IPC. Branch: release/microkernel · PROFILE=microkernel.

🔬
Pure Microkernel
Stable
Only IPC and memory management in kernel space. Every driver, filesystem, and network stack lives in user-space shards. Maximum fault isolation — a crashed driver is restarted without rebooting.
Pure µK<512KBIPC-only
🔀
Hybrid Microkernel
Stable
Performance-critical drivers (GPU, NIC) run in kernel space while all others remain in user-space. Balances isolation and throughput — the SigmaOS default production configuration.
HybridDefault ConfigBalanced
🧱
Modular Microkernel
Stable
Kernel modules loaded/unloaded at runtime without rebooting. Start with a minimal base and add shards on demand — NVMe driver, network stack, or VirtIO GPU — via sigma-pkg load <shard>.
Hot-LoadRuntime Modulessigma-pkg
🔩
Exokernel / Minimalist
Preview
Absolute minimum viable kernel. No hardware abstraction — applications directly manage physical pages, CPU time-slices, and device DMA. For research and ultra-low-latency deployments. Footprint <32 KB.
Exokernel<32KBResearch
🔌
Microkernel with POSIX Layer
Stable
Pure microkernel base topped with a POSIX-lite compatibility shard. Run unmodified POSIX C applications with full isolation guarantees. Supports pthreads, fork/exec, pipe, socket, file descriptors.
POSIX-litefork/execpthreads

🖥️ Kernel Formats

Raw SigmaOS kernel images compiled with different architectural philosophies. Freestanding, no glibc, PQC-attested. Choose the kernel model that matches your isolation, performance, and footprint requirements.

🏗️
Monolithic
Stable
All subsystems — scheduler, memory, drivers, FS, network — compiled into one address space. Maximum raw throughput. The default SigmaOS kernel for desktops and servers. Based on MLFQ+EDF+CFS schedulers and 4-level paging with ASLR.
MLFQ+EDF+CFSASLRW^Xx86_64
🔬
Microkernel
Stable
Only IPC, memory management, and basic scheduling in kernel-space. All drivers and services in isolated user-space shards communicating via sigma-bus. <512 KB kernel binary. SPIFFE workload identities for every shard.
<512KBSPIFFEsigma-bus IPC
🔀
Hybrid
Stable
Performance-critical paths (GPU, NIC, storage) in kernel space; everything else isolated in user-space shards. The production default for cloud and workstation profiles. Balanced between monolithic speed and microkernel safety.
HybridProduction DefaultBalanced
🔩
Exokernel
Preview
The kernel multiplexes hardware with minimal abstraction. Applications manage their own CPU time-slices, physical pages, and device DMA directly. Highest possible performance ceiling; intended for systems researchers and ultra-latency workloads.
ExokernelResearchUltra-Low Latency
⚛️
Nanokernel
Preview
Even smaller than a microkernel — only interrupt routing and context switching remain. All other OS functionality, including memory management, lives outside. Footprint under 8 KB. Used as a hypervisor foundation for Type-1 virtualisation.
Nanokernel<8KBHypervisor Base
🧱
Modular
Stable
A loadable-module kernel. The base image is minimal; additional subsystems (NVMe, Wi-Fi 6, VirtIO-GPU) are loaded as kernel modules at boot or runtime via sigma-pkg load <module>. Keeps the base small without sacrificing capability.
Loadable ModulesRuntime Loadsigma-pkg
🏛️
Monolithic + Modular
Stable
The best of both worlds — a high-performance monolithic core with a loadable module system on top. Similar to Linux's approach. Core subsystems always present; optional drivers loaded on demand. The recommended kernel for general-purpose workloads.
Best of BothRecommendedLinux-like
