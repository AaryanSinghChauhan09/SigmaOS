# Getting Involved

SigmaOS is a community-driven project, and we welcome contributions from everyone. There are many ways to get involved, regardless of your technical background or experience level.

## Ways to Contribute

### Code Contributions

- **Bug Reports**: If you find a bug, please report it on our [issue tracker](https://github.com/AaryanSinghChauhan09/SigmaOS/issues) with detailed information about how to reproduce it.
- **Pull Requests**: We welcome pull requests for bug fixes, new features, and improvements. Please follow our [contributing guidelines](Contributing).
- **Testing**: Help test pre-release versions and provide feedback on stability and functionality.

### Documentation

- **Wiki Improvements**: Help improve our documentation by fixing typos, adding examples, or expanding on existing topics.
- **Translation**: Help translate documentation and user-facing strings into other languages.
- **Tutorials**: Write tutorials and guides for specific use cases or configurations.

### Community Support

- **Forum Support**: Help answer questions from other users in our forums and discussion channels.
- **Knowledge Sharing**: Share your experiences, configurations, and solutions with the community.
- **Mentoring**: Help new contributors get started with the project.

### Design and User Experience

- **Zenith Desktop**: Contribute to the Zenith compositor and desktop environment design.
- **Accessibility**: Help improve accessibility features and screen reader integration.
- **Theme Development**: Create and share custom themes for the Zenith desktop.

## Development Workflow

### Setting Up Your Development Environment

1. Fork the repository on GitHub
2. Clone your fork locally
3. Set up the build environment according to the [build instructions](BUILD)
4. Run the test suite to ensure everything works

### Making Changes

1. Create a new branch for your changes
2. Make your changes following our [coding standards](DEVELOPMENT_GUIDE)
3. Add tests for new functionality
4. Ensure all tests pass
5. Commit your changes with a clear message
6. Push to your fork and submit a pull request

### Code Review Process

All pull requests go through code review before being merged. Be prepared to:

- Respond to review comments
- Make requested changes
- Explain your design decisions
- Update documentation as needed

## Communication Channels

- **GitHub Issues**: For bug reports and feature requests
- **GitHub Discussions**: For general questions and community discussions
- **Pull Requests**: For code contributions and technical discussions
- **Email**: aaryansinghchauhan09@gmail.com for security issues and private matters

## Recognition

Contributors who make significant contributions to SigmaOS will be recognized in our contributor list and may be invited to become maintainers for specific components.

## First Steps

If you're new to open source or to SigmaOS specifically, here are some good places to start:

1. Read the [About SigmaOS](About-SigmaOS) page to understand the project
2. Browse the [Installation Guide](Installation-Guide) to try SigmaOS
3. Look at [good first issues](https://github.com/AaryanSinghChauhan09/SigmaOS/issues?q=is%3Aopen+is%3Aissue+label%3A%22good+first+issue%22) for beginner-friendly tasks
4. Join our community discussions to ask questions and learn from others

Thank you for your interest in contributing to SigmaOS!
