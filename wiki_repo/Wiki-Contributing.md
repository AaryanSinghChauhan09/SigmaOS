# Wiki:Contributing

This page is the starting point for those willing to contribute to the SigmaOS Wiki.

## Why Contribute?

Contributing to the wiki helps:
- Improve documentation for all users
- Share your knowledge and experience
- Make SigmaOS more accessible to newcomers
- Create a comprehensive knowledge base
- Help the project grow and succeed

## Ways to Contribute

### Fix Typos and Grammar
Small improvements make a big difference:
- Fix spelling mistakes
- Correct grammar errors
- Improve sentence structure
- Fix broken links

### Expand Existing Articles
Add more information to existing pages:
- Add missing details
- Include examples
- Clarify confusing sections
- Add troubleshooting tips

### Create New Articles
Write new documentation:
- Tutorial articles
- How-to guides
- Configuration examples
- Troubleshooting guides
- Feature explanations

### Translate Documentation
Help make SigmaOS accessible in other languages:
- Translate existing articles
- Create language-specific guides
- Adapt examples for local contexts

### Add Screenshots and Images
Visual aids improve understanding:
- Add screenshots of UI elements
- Include diagrams for complex concepts
- Add illustrative images for hardware

### Review and Update
Keep documentation current:
- Update outdated information
- Remove deprecated content
- Add information about new features
- Verify instructions still work

## Getting Started

### GitHub Wiki Basics
The SigmaOS Wiki is hosted on GitHub. To contribute:

1. **Navigate to the Wiki**: Go to https://github.com/AaryanSinghChauhan09/SigmaOS/wiki
2. **Find an Article**: Browse or search for the article you want to edit
3. **Edit the Article**: Click the "Edit" button (pencil icon)
4. **Make Changes**: Make your improvements using Markdown
5. **Preview**: Use the preview tab to see your changes
6. **Commit**: Write a clear commit message and save

### Editing via Git
For more advanced editing:

1. **Clone the Wiki Repository**:
   ```bash
   git clone https://github.com/AaryanSinghChauhan09/SigmaOS.wiki.git
   cd SigmaOS.wiki
   ```

2. **Edit Files**: Edit `.md` files in your preferred editor

3. **Commit Changes**:
   ```bash
   git add .
   git commit -m "Your descriptive commit message"
   git push origin main
   ```

## Writing Guidelines

### Style Guide
Follow these guidelines for consistent documentation:

- **Clear and Concise**: Write clearly and avoid unnecessary words
- **Active Voice**: Use active voice when possible
- **Present Tense**: Use present tense for general information
- **Step-by-Step**: Use numbered lists for procedures
- **Code Blocks**: Use fenced code blocks for commands and code
- **Headings**: Use heading hierarchy logically

### Article Structure
Organize articles with a clear structure:

1. **Introduction**: Brief overview of the topic
2. **Prerequisites**: What the reader needs before starting
3. **Main Content**: The core information
4. **Examples**: Practical examples and use cases
5. **Troubleshooting**: Common issues and solutions
6. **See Also**: Links to related articles

### Formatting Conventions

#### Commands
Display commands in code blocks with shell type:

```bash
sudo sigpkg install package-name
```

#### File Paths
Display file paths inline: `/etc/sigma-config/config.toml`

#### Configuration
Show configuration in appropriate language syntax:

```toml
[desktop]
theme = "dark"
```

#### Notes and Warnings
Use blockquotes for important information:

> **Note**: Important information
> 
> **Warning**: Potential issues or risks

## Code of Conduct

All wiki contributions must follow the [Code of Conduct](Code-of-Conduct):

- Be respectful and constructive
- Welcome newcomers and help them learn
- Focus on what is best for the community
- Show empathy and understanding

## Review Process

### Quality Standards
Contributions should meet these standards:

- **Accuracy**: Information must be accurate and up-to-date
- **Clarity**: Writing should be clear and easy to understand
- **Completeness**: Articles should cover the topic adequately
- **Consistency**: Follow established style and formatting
- **Testing**: Instructions should be tested when possible

### Peer Review
For significant changes:
- Get feedback from other contributors
- Consider different perspectives
- Be open to suggestions and improvements
- Update based on feedback

## Common Mistakes to Avoid

### Technical Issues
- **Broken Links**: Always verify links work
- **Outdated Information**: Check if information is still current
- **Incorrect Commands**: Test commands before including them
- **Missing Context**: Provide enough context for understanding

### Writing Issues
- **Too Technical**: Avoid unnecessary jargon
- **Too Vague**: Be specific and detailed
- **Poor Structure**: Use logical organization
- **Inconsistent Formatting**: Follow established conventions

## Advanced Contributions

### Complex Articles
For complex documentation:
- Plan the article structure before writing
- Use diagrams and illustrations
- Include multiple examples
- Provide troubleshooting guidance
- Link to related resources

### Series of Articles
For related content:
- Create a series of linked articles
- Use consistent naming conventions
- Include navigation between articles
- Maintain consistent style across series
