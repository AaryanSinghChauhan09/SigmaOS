## Conflict Resolution Policy

When merging branches, the following precedence rules apply:

1. **Source files (`.rs`)** — prefer incoming branch (`theirs`) to capture new features/fixes
2. **Documentation (`.md`, wiki files)** — prefer `main` (`ours`) as it is more up-to-date
3. **Security fixes** — always prefer incoming branch regardless of file type
4. **No-std compliance** — prefer `core::` over `std::` in kernel/klib code
5. **Complementary changes** — merge manually when both sides add distinct value
