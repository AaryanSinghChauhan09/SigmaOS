# Contributing to SigmaOS Documentation

Thank you for contributing to SigmaOS documentation!

## Guidelines

### Documentation Standards

- Use clear, concise language
- Include code examples where appropriate
- Link to related documentation
- Keep documentation current with code changes

### Process

1. Fork the repository
2. Create a feature branch: `git checkout -b docs/your-topic`
3. Make your changes
4. Validate links: `npm run validate-links` (or run local checks)
5. Commit with conventional message: `docs: add topic documentation`
6. Push and open a pull request

### Structure

- Place new documentation in appropriate `docs/` subdirectory
- Use markdown for all documentation
- Use descriptive filenames
- Add content to relevant README.md indices

### Validation

Before committing:
- Ensure all links are valid (checked by CI)
- Follow markdown formatting conventions
- Run local validation if available

## Questions?

- Open an issue for discussion
- Check existing documentation for similar content
- Ask in the project's communication channels

Thank you for improving SigmaOS documentation!
