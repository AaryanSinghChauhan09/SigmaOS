## 2026-07-16 - Environment Variable Sanitization in Graphical Elevation Engines
**Vulnerability:** `GksuSecurityGuard::sanitize_environment` in `libgksu.rs` previously checked a hardcoded subset of dangerous variables (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH`, `RUBYLIB`, `PERL5LIB`) and relied on `allowed_keys.contains(k)`. If an elevation caller allowed dynamic linker, interpreter, shell, or system variables (`LD_AUDIT`, `DYLD_INSERT_LIBRARIES`, `NODE_OPTIONS`, `IFS`, `BASH_ENV`, `GCONV_PATH`), or if keys/values contained embedded NUL bytes or control characters, malicious shared objects or commands could be loaded or executed under root privileges.
**Learning:** Checking only a static list of explicit key names and trusting caller-supplied allowed key lists allows bypasses when callers include dangerous or malformed environment keys.
**Prevention:** Always enforce a central strict filter (`is_dangerous_environment_variable`) in privilege escalation routines that strips all dynamic loader (`LD_*`, `DYLD_*`), interpreter (`PYTHON*`, `PERL*`, `RUBY*`, `NODE_OPTIONS`), shell (`IFS`, `BASH_ENV`, `ENV`, `BASH_FUNC_*`), and system path (`GCONV_PATH`, `HOSTALIASES`, etc.) variables as well as any key or value containing NUL bytes or control characters, regardless of caller allowed lists.
